# خطة النقل لـ ArabGT — من المختبر للشغل الفعلي

> **القرار المعماري المعتمد:** الشغل التفاعلي والمتوازي على **Cursor وClaude معاً** (ميكانيكا git وMCP مشتركة) — والأتمتة كلها على **Claude** (الحراس الصارمين والتشغيل بلا واجهة مش مدعومين بـ Cursor).
> مراحل بالترتيب، بلا تواريخ — كل مرحلة إلها **بوابة نجاح** لازم تتحقق قبل اللي بعدها.

## المرحلة 0 — القرارات والمفاتيح (بعد موافقة العرض)

| البند | القرار المطلوب | من مين |
|---|---|---|
| الريبو الرائد | **كود ArabGT = تطبيق Flutter + باك إند Django** — منبلش بريبو واحد (اقتراح: الموبايل أولاً — أقل خطورة على البيانات)، والثاني بيلحق بنفس الوصفة | أمجد |
| فوترة الـ AI للأتمتة | مفتاح API مركزي باسم الفريق (فوترة شفافة لكل أنبوب) | أمجد/الإدارة |
| أسماء الإنتاج الحقيقية | قائمة بأسماء بيئات/قواعد/مساحات production الفعلية — **غذاء الحراس** | عمر + التيم |
| صلاحيات الربط | Sentry الشركة **قراءة فقط** كبداية؛ Linear بصلاحيات محدودة | أمجد |

**بوابة النجاح:** موافقة مكتوبة عالنطاق + المفاتيح بإيدنا.

> **ملاحظة المسارين:** كل مرحلة تحت بتنطبق على الريبوهين بأدوات كل واحد — الموبايل: `flutter analyze` + `flutter test` + integration tests + Test Lab؛ الباك إند: `ruff` + `pytest` + فحوصات Django. **وحراس الـ production أشد أهمية بالباك إند**: منع `manage.py migrate/shell` على بيئات الإنتاج، منع أي أمر فيه `DATABASE_URL` أو أسماء prod DBs الفعلية — بتنضاف لأنماط الحارس بالمرحلة أ.

## المرحلة أ — الأساسات على الريبو (يخدم Cursor وClaude معاً)

1. **Claude يدرس الكود كامل** ويكتب `CLAUDE.md` حقيقي: البنية، الأعراف، الممنوعات — ويُراجع من عمر والتيم
2. **مرآة لـ Cursor**: نفس القوانين بـ `.cursor/rules` — عشان مستخدمي Cursor ياخدوا نفس الذاكرة (ملفين، مصدر حقيقة واحد)
3. **الصلاحيات والحراس**: `.claude/settings.json` بالريبو — ملفات التعديل المسموحة، وحراس production بالأسماء **الحقيقية** من المرحلة 0 (exit 2 قبل التنفيذ)
4. **تفعيل التوازي**: skill الـ `/parallel-tasks` (بسياسة "ولا agent-ين على ملف") + توثيق workflow الـ worktrees للفريق — بيشتغل مع جلسات Claude ومع Cursor (نوافذ/background agents على worktrees)

**بوابة النجاح:** مطوّرَين (عمر + واحد كمان) اشتغلوا أسبوع بالإعداد الجديد — والحراس انفحصوا بإطلاق نار تجريبي.

## المرحلة ب — بوابات الـ PR (أتمتة = Claude)

1. فحوصات حتمية بكل PR: `flutter analyze` + `flutter test` (GitHub Actions)
2. **مراجع Claude** على كل PR (claude-code-action بمفتاح الفريق) — بتعليمات مخصصة: أنماط Flutter، حساسيات الترجمة والـ RTL
3. **Branch Protection**: الدمج مقفول لحد ما البوابات تخضرّ — على `main` و`staging`

**بوابة النجاح:** أسبوعين من الـ PRs عالنظام — والفريق شايف قيمة الملاحظات (مش مزعوج منها).

## المرحلة ج — الإشارات (أتمتة = Claude)

1. **Sentry MCP** (قراءة فقط): triage الأخطاء بالحوار + **التقرير الصباحي** يومياً على قناة Slack
2. **Linear MCP**: skill التذاكر بالعامية **للفريق كله** (أحمد وأمجد كمان — مش بس المطورين) + الفرز الأوتوماتيكي للتذاكر الجديدة بتعليق تدقيق إلزامي
3. حراس المساحات مضبوطين بأسماء الشركة الحقيقية

**بوابة النجاح:** الصبحية صارت عادة الفريق + التذاكر الجديدة بتنفرز بدون شكاوى من الفرز.

## المرحلة د — QA على نطاق (أتمتة = Claude + أدوات مجانية)

1. **الرحلات الذهبية** بالتطبيق (بحث → تفاصيل → تواصل؛ إعلان → حجز...) — Claude يكتبها كـ integration tests من وصف بالعامية، التيم يراجع التغطية
2. **الفحص الليلي** على iOS وAndroid بتقارير لكل منصة (GitHub Actions)
3. **الأسبوعي على أجهزة حقيقية** (Test Lab) — قائمة الأجهزة من إحصائيات مستخدمي ArabGT الفعلية
4. الفحص البصري (عيون الـ AI) بجدولة — عربي وإنجليزي، خصوصاً شاشات المتجر

**بوابة النجاح:** أول bug حقيقي بينمسك بالفحص الليلي/الأسبوعي قبل ما يوصل مستخدم.

## المرحلة هـ — سيرفر الأتمتة (AWS) والحلقات الكاملة

1. **EC2 صغير دايم الصحو** (t4g.small بيكفي — الشغل الثقيل عالـ API): مستمعي webhooks (Sentry/Linear/GitHub) + الجدولة + الأنابيب بلا واجهة + توصيل Slack
2. **الحلقات الكاملة تشتغل بالتدريج**: crash → تشخيص + PR جاهز؛ تذكرة بعمود "Ready for AI" → أسئلة → spec → PR — **والدمج دايماً بشري**
3. فشل فحص ليلي → إشعار + تذكرة Linear بتنفتح لحالها

**بوابة النجاح:** أسبوع كامل والمصنع شغال والفريق عند القرارات بس.

## الثوابت بكل المراحل

- **production خط أحمر محفور** — بالحراس والعزل، مش بالوعود
- **كل شي عبر PR** — ولا سطر AI بيدخل بدون بوابات ومراجعة بشرية
- **التوثيق أول بأول**: كل مرحلة بتتوثق بوثيقة نقل (شو انعمل، ليش، شو النتيجة) وبتنضاف لدفتر NotebookLM — نفس نمط المختبر
- **قياس قبل التوسع**: ما ننتقل لمرحلة قبل ما بوابة اللي قبلها تتحقق فعلياً
