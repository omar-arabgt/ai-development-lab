## شريحة 1 — الغلاف

**شو بتحكي:**
"اليوم بدي أفرجيكم شغل صار فعلياً — مش أفكار ولا slides نظرية. كل اللي رح تشوفوه **مبني ومركّب ومجرّب على الريبوهات تبعتنا** — الموبايل والباكند. الفكرة الكبيرة: كيف منخلي الـ AI يشتغل معنا كعضو فريق منضبط — بيعرف الكود تبعنا، ملتزم بقوانيننا، وممنوع يقرّب على الخطوط الحمر. ورح نمشي بالترتيب: الأساس، كيف منشتغل، الـ review والحماية، الـ testing، وبالآخر الـ automation الكاملة."

**لقطة تركيز:** أول جملة بتحدد نبرة الاجتماع كله — "مبني ومجرب" مش "اقتراح".

## شريحة 2 — The Foundation (الطبقات الخمسة)

**شو بتحكي:**
"الـ AI الخام بدون ضبط عنده ثلاث مشاكل: ما بيعرف مشروعك، **بيخمّن** لما ما يعرف، وصلاحياته مفتوحة. الحل خمس طبقات — وكلها **ملفات نصية جوّا الريبو**: بتتراجع بالـ PR زي أي كود، وأي حدا يعمل clone بتوصله جاهزة.

واحد واحد: **الـ Rules** — ذاكرة المشروع، بتنحقن تلقائياً بكل محادثة: الـ stack، القوانين الإلزامية زي إنه الـ navigation بس من الـ router المركزي، والقانون الذهبي *'مش متأكد؟ اسأل — لا تخمّن'*. **الـ Hooks** — حراس بيشتغلوا **قبل تنفيذ أي أمر** وبيقدروا يرفضوه: فحص نصي محايد، بيفحص الأمر مش النية — يعني حتى لو الـ AI انخدع، الأمر الممنوع **ما بينفذ فيزيائياً**. **الـ Subagents** — متخصصين بأدوار ضيقة: الـ reviewer قراءة فقط وما بيقدر يعدل كود. **الـ Skills** — إجراءات متكررة مكتوبة مرة وحدة بسياسة الفريق، بتنادى بكلمة زي `/sentry-sweep`. **والـ MCP** — الوصلة الحية مع Sentry وLinear: بيقرأ أخطاء حقيقية وبيفتح تذاكر حقيقية، تحت الحراس.

والبوكس الذهبي تحت: هاد كله **مركّب فعلياً عالريبوهين** — والحراس مجربين بالرصاص الحي: **21 من 21 test نجحوا**، صد ومرور."

**لو انسألت "شو يعني بيخمن؟":** "مثلاً طلب مش واضح إذا للموبايل ولا للويب — بدل ما يختار عشوائي ويكمل، القانون بيجبره يوقف ويسأل. التخمين الصامت هو أخطر شي بالـ AI وسكّرناه بالكتابة."

## شريحة 3 — Multi-Agent

**شو بتحكي:**
"طيب كيف منشتغل فيه يومياً؟ مش agent واحد — **كذا agent بالتوازي** (Cursor بيدعم لحد 8 بالـ Multitask). والسر إنه ما يصير تضارب: كل agent بياخد **git worktree** — نسخة مجلد كاملة من الريبو على branch مستقل، فبيعدل ويفحص ويعمل commit بلا ما يلمس شغل حدا. وفي قانون توزيع صارم محفور بالـ rules: **ممنوع ملف واحد يكون عند اثنين** — لو مهمتين بيلمسوا نفس الملف، بياخدهم agent واحد بالتسلسل. وحتى الـ database معزولة — كل agent نسخة خاصة، فالـ dev الأصلية ما بتنصاب.

والدليل مش نظري — **البوكس الذهبي**: سحبنا 3 production bugs حقيقية من Sentry حسب التكرار، توزعوا على 3 agents بالتوازي، كل واحد: كتب test بيفشل بيثبت الباغ، صلّح، شغّل كل الفحوصات، وفتح PR. **ثلاث PRs بجلسة وحدة** — والتذاكر بـ Linear تحركت لحالها لحالة 'In Review from AI'."

**لقطة تركيز:** وقف عند "تست بيفشل أولاً" — هاي بتفرق المحترف عن الهاوي: التست لازم يثبت الباغ قبل الحل، عشان نعرف إنه الحل فعلاً حل.

## شريحة 4 — PR Review + قصة Bugbot

**شو بتحكي:**
"كل PR بينفتح — **الـ reviewer تبعنا بيصحى لحاله على GitHub**: بيشتغل بـ Cursor CLI بمفتاح API محفوظ كـ secret. مش بس بيقرأ الـ diff — **بيتجول بالريبو**، بيقارن بقوانيننا (بيعرف الـ ArabgtGo ومجلدات الاستثناء وحدود الـ api/web)، وبيكتب تعليق واحد بينتهي بحكم صريح: **READY أو NOT READY**. والرفض مش رأي — **بيفشّل الـ check وبيقفل الدمج**. ولو رفض، بيرفق **fix prompt جاهز**: نسخ، لصق بـ Cursor، انحل.

وذكاء إضافي: التحديثات بتتراجع **تزايدياً** — دفعة جديدة عالـ PR بتراجع بس الـ diff الجديد وبيتحقق من ملاحظاته القديمة، فأسرع وأرخص.

هلق سؤال الفلوس — في منتج جاهز اسمه **Bugbot** من Cursor بيعمل مراجعة: **$1.20 لكل مراجعة** بلا سقف. 40 PR بالشهر = $48. تبعنا بيعمل نفس الشغل أعمق بـ **$8-20** — لأننا مندفع الاستهلاك الفعلي بلا هامش منتج. والقرار اللي وصلنا إله: **هجين** — تبعنا على كل PRs الشغل اليومي، وBugbot **بس** عند ترقية staging لـ production، بالمناداة: عقل ثاني مستقل عند أخطر بوابة، بكم دولار بالشهر."

## شريحة 5 — Protection (البوابات)

**شو بتحكي:**
"كل اللي حكيته لهلق بيشتغل على أجهزتنا. هاي الشريحة عن الطبقة اللي **برا أجهزتنا كلها — عند GitHub نفسه**، فبتنطبق على الكل: بشر وAI، من أي جهاز. أربع قوانين: **ممنوع push مباشر** عالبرانشات الحساسة — بس PR. **الفحوصات required** — check أحمر يعني زر الـ merge معطّل فيزيائياً. **مراجعة بشرية إلزامية** — الـ AI بيفتح PR بس عمره ما بيدمجه. **وبوابة الترقية**: production بياخد من مصدر واحد بس — staging. أي PR من غير staging بينرفض فوراً.

وهون أول قرار مطلوب: هالحماية عالريبوهات الخاصة بدها **خطة GitHub Team — $4 للمستخدم بالشهر**. بدونها كل هالبوابات بتضل تحذيرات؛ معها بتصير قانون."

## شريحة 6 — Testing Layers

**شو بتحكي:**
"الفحص عنا ثلاث طبقات، ولازم تعرفوا الفرق: **Unit tests** — فحص المنطق الصافي، آلاف الفحوصات بالدقيقة، بلا أي جهاز. **Widget tests** — الشاشة بتترسم بالذاكرة: 'عنوان 200 حرف بيعمل overflow؟' — سريع وبلا simulator. **والـ Journeys بـ Patrol** — روبوت بيمشي رحلة المستخدم **الفعلية** على simulator حقيقي: يفتح التطبيق، يكبس Allow للإشعارات، يسجل دخول، يفتح خبر بالـ WebView. وPatrol — إطار **مجاني مفتوح المصدر** — هو اللي خلى هالرحلة ممكنة: فحص Flutter العادي أعمى عن كل شي native — نافذة الأذونات بتجمده — Patrol أعطاه إيد بتوصل.

والجدولة عالسرعة: **كل PR** الطبقات السريعة (قروش)، **كل ليلة** الرحلات كاملة عالمحاكيات، **أسبوعياً** نفس الرحلات على أجهزة حقيقية، **وعند الطلب** بزر."

**لو انسألت "ومين بيكتب التستات؟":** "الـ qa-engineer subagent — والـ AI بيكتب التست مرة وحدة، وكل تشغيل بعدها حتمي رخيص بلا AI. الذكاء وقت الكتابة، الغباء الرخيص وقت التكرار."

## شريحة 7 — المنصات والتكلفة

**شو بتحكي:**
"وين بتركض الأجهزة الحقيقية وبكم؟ عملنا سيناريو مرجعي متعمد أكبر من حاجتنا: 10 أجهزة حقيقية يومياً، ربع ساعة للجهاز، طول الشهر. **Firebase Test Lab**: بهالسيناريو ~$300 — بس بحجمنا الفعلي **صفر**، لأنه الحصة المجانية اليومية (10 وهمي + 5 حقيقي) بتغطينا، وهو أصلاً نفس الـ Firebase اللي منستعمله. **AWS Device Farm**: $765 لنفس الشغل — مرفوض. **BrowserStack**: اشتراك ثابت $199 حتى لو ما استعملناه — وبيربح **بس** فوق 40 ساعة جهاز-حقيقي بالشهر. احنا أدنى بكثير — وحاطين هالعتبة **كإشارة تحويل**: يوم منوصلها، منفتح الملف. **وسيرفرات GitHub المستأجرة**: Linux شبه ببلاش، بس دقيقة الـ **macOS بـ $0.08** — ساعة iOS ليلية = ~$105 بالشهر.

وهون البوكس الذهبي — **نموذج الـ Mac mini**: جهاز بـ $600 مرة وحدة كـ self-hosted runner: دقايق الماك بتصير **صفر للأبد**، الـ builds أسرع، **وبيحل مشكلة ثانية ببلاش**: هو جوّا شبكة المكتب، فبيوصل لداتابيس staging بلا ما نفتح أي منفذ. بيسدد حاله بستة أشهر."

## شريحة 8 — عملية Test Lab

**شو بتحكي:**
"كيف بتصير عملياً؟ خط واحد: **GitHub Actions بيبني** التطبيق → **Patrol بيغلف** الرحلات بالصيغة اللي Google بدها → **رفع** بأمر واحد → **جهاز Samsung أو iPhone حقيقي** عندهم بيشغل الرحلة → وبيرجعلنا **فيديو + logs + تقرير**. ونقطة للأمان بتهمكم: هم بيستقبلوا **الملف المبني بس** — الـ source code عمره ما بيطلع من الشركة.

وطريقتين تشغيل: **مجدولة** — أسبوعياً أوتوماتيك والتقرير مستنينا الصبح. **أو بزر** — Run workflow عند الطلب: على PR بالـ staging منقدر نختار نشغل **بس رحلات الميزة اللي تغيرت** — خمس دقايق جهاز بدل خمسين — أو التطبيق كامل. خيارنا بكل تشغيلة."

## شريحة 9 — Sentry + PostHog

**شو بتحكي:**
"هلق المراقبة. **Sentry** بيجاوب 'شو انكسر؟' و**PostHog** بيجاوب 'شو المستخدمين عم يعملوا؟' — والاثنين صاروا أوتوماتيك: **كنس يومي الساعة 7** — أعلى الأخطاء بتتحول تذاكر Linear لحالها: مع **dedupe** (الموجود ما بينكرر)، label باسم Sentry، والتذكرة **مشكلة-فقط** بدون اقتراح حلول — سياسة فريق. وبآخر كل تذكرة **قسم close-out**: رقم الخطأ ورابطه — عشان لما الحل يتأكد، **إنسان** يفتح الرابط ويعمل resolve. **وتقرير صباحي** قبل الدوام: أخطاء الأمس مرتبة + مين إله تذكرة + سلوك المستخدمين من PostHog — صحة النظام والناس بنظرة وحدة.

والسطر الأحمر بالشريحة مقصود: **Sentry قراءة فقط للـ AI — من أول السلسلة لآخرها.** يفتح تذاكر؟ آه. يعمل resolve أو يعدل؟ **أبداً — بشري دايماً.**"

## شريحة 10 — Real-time Pipeline

**شو بتحكي:**
"وهاي الشريحة اللي بتجمع كل شي — **من الخطأ للحل بدقايق**: خطأ بيوقع بالـ production → **Sentry alert** (مضبوط على الأخطاء الجديدة بس، error وفوق — عشان ما نغرق بالضجيج) → بيضرب webhook على **relay صغير** — كود 20 سطر على Lambda بالـ AWS تبعنا أو Cloudflare Worker، مش سيرفر منديره — → الـ relay بيكبس زر **GitHub Action** → والـ agent بينفذ السلسلة: تذكرة Linear → In Progress → branch من **staging** (الأقرب للكود المكسور فعلياً) → test بيفشل أولاً → الحل → كل الفحوصات → **PR على qa** — عشان الـ dev ما ينزعج بشغلنا اليومي — → تعليق مفصل عالتذكرة بالسبب والملفات ورابط الـ PR → الحالة **In Review from AI**.

والباكند بده database؟ احنا على **AWS RDS** — وAmazon أصلاً بتاخد **snapshot ليلي** لحالها. فالخط بيعمل **clone مؤقت من صورة البارحة بأمر واحد** — سريع مهما كان الحجم، بلا dump ولا نقل داتا — الـ agent بيشتغل عالنسخة بس، وبتنحذف بنهاية التشغيلة. **staging نفسها ولا بتنلمس ولا بتنكشف.** (بس بدها الـ runner يكون جوّا الـ VPC — EC2 صغيرة بصلاحية IAM على قدها.) وصمامات الأمان: تشغيلة وحدة لكل خطأ، **ولا PR أحمر بينفتح أبداً**، والدمج بضل قرارنا."

**ولو حدا ذكر تكامل Sentry×Cursor الجاهز:** "صحيح — Seer بيقدر يسلم الباغ لـ Cursor Cloud Agent مباشرة وبيفتح PR، ومفعلينه **كزر سريع للحالات الفردية**. بس الخط الرئيسي تبعنا لأنه الجاهز بيصلح الكود وما بيدير **العملية**: لا طقوس Linear تبعتنا، ولا استراتيجية البرانشات، ولا نسخة الداتابيس. السرعة من الجاهز — والانضباط من خطنا."

**لقطة تركيز:** خلص الشرح بجملة "البشر بيدخلوا مرتين بالضبط: يوافقوا عالدمج، ويسكّروا الخطأ" — هاي بتطمّن أي حدا خايف من الأتمتة.

## شريحة 11 — Decisions

**شو بتحكي:**
"كل اللي شفتوه **مبني وجاهز** — هاي الستة هم المفاتيح اللي بتشغله رسمياً: **واحد** — ترقية GitHub لـ Team: $4 للمستخدم، وبدونها البوابات بتضل تحذيرات. **اثنين** — تفعيل الـ required checks: 10 دقايق أدمن. **ثلاثة** — مفتاحين كـ secrets: الكنس وخط الإصلاح بيشتغلوا. **أربعة** — Bugbot بوضع المناداة عند بوابة production: دولارات معدودة. **خمسة** — مقعد service account اسمه ai-ci: المفاتيح ملك الشركة مش ملك شخص، وفاتورة الـ CI سطر واحد نظيف. **وستة** — الـ Mac mini: قرار استثماري ممكن يتأجل، بس حسبته قدامكم — بيسدد حاله بنص سنة.

الثلاثة الأولى هم الأساس — أقل من ساعة شغل أدمن وبيقلبوا كل شي من تجربة لنظام رسمي."

## أسئلة متوقعة بعد العرض — أجوبة بجيبك

- **"وشو بيمنع الـ AI يعدل الحراس نفسهم؟"** ← "الحراس ملفات بالريبو — أي تعديل بيبين بالـ diff وبيمرق بمراجعة بشرية، والعمليات الحساسة أصلاً موقوفة على موافقة. وفي قصة حلوة: الحارس صدّ الـ AI اللي كتبه — مرتين."
- **"ليش مش منستعمل منتجات جاهزة بس؟"** ← "استعملنا وين بتستاهل (Bugbot عند القمة، Test Lab للأجهزة) — بس القلب معمول عنا لأنه بيعرف قوانيننا وبنملكه وبيكلف كسور المنتجات الجاهزة."
- **"قديش وقت صيانة هالنظام؟"** ← "الملفات بتتحدث مع المشروع زي أي كود — بالـ PRs العادية. مافي سيرفرات منديرها: كل شي بيركض عند GitHub وGoogle."
- **"لو الـ AI API وقع أو غلط؟"** ← "الفحوصات الحتمية (tests) ما إلها علاقة بالـ AI — بتضل شغالة. ومراجعة الـ AI لو تعطلت في زر re-run، ولو حكم غلط الدمج أصلاً بده موافقة بشرية فوقه."
