# 1. التجهيز: المعرفة، الحدود، الحراس

## شو بتحكي

"أول ما بتفتح جلسة AI جديدة — Claude أو Cursor — هو ما بيعرف عن مشروعنا ولا شي: لا الـ structure، ولا الـ architecture، ولا طريقة كتابة الكود تبعتنا. فأول شي منعمله: منكتبله **تعريف كامل للمشروع بملف بيعيش جوا الـ repo نفسه** — الـ structure وكيف الـ features بتتوزع، الـ conventions والـ patterns المعتمدة، والممنوعات والخطوط الحمرا. النتيجة: من أول ثانية بأي جلسة، الـ AI بيشتغل كأنه developer معنا من سنة. وبما إنه الملف بالـ repo — أي حدا يعمل clone، المعرفة بتيجي معه: **أصول تبعت الفريق، مش إعدادات على جهاز حدا**.

فوق المعرفة في حدود: **Permissions** — قوائم صريحة شو مسموح ينفذ بدون سؤال وشو ممنوع نهائياً، وأي ملفات إله حق يعدلها. وفوقها أقوى طبقة: **Production guards** — كود بيفحص كل عملية **قبل تنفيذها**، وأي شي بيلمح لـ production بينمنع فوراً. مش سياسة بـ wiki — النظام نفسه بيرفض."

## وين بينعرف

| الشي | الملف/المكان بالضبط | by default ولا منكتبه؟ | الأحسن النا |
|---|---|---|---|
| ذاكرة المشروع — Claude | `CLAUDE.md` بجذر الـ repo | **منكتبه** (الـ AI بيدرس الكود وبيكتب مسودة، إحنا منراجع) | **الاثنين** — نفس المحتوى بملفين |
| ذاكرة المشروع — Cursor | `.cursor/rules/` بجذر الـ repo (ملفات .mdc) | **منكتبه** (مرآة لنفس قوانين CLAUDE.md) | ↑ |
| Permissions + file scopes — Claude | `.claude/settings.json` بجذر الـ repo → `permissions: { allow / ask / deny }` | **منكتبه** — وبينلجن مع الـ repo فبيوصل للكل | **Claude أدق** — قوائم صريحة بمستوى الأمر والملف |
| Permissions — Cursor | إعدادات التطبيق (Agent auto-run allowlist) | إعداد بالواجهة | ⚠️ ملاحظة: إعدادات Cursor **على الجهاز مش بالـ repo** — ما بتنتشر مع الفريق تلقائياً |
| Production guards (hooks) | `.claude/settings.json` بالـ repo → `hooks: PreToolUse` — سكربت bash بيفحص العملية وبيرجع exit 2 للمنع | **كود منكتبه** — سطور قليلة، بتنلجن مع الـ repo | **Claude فقط** — Cursor ما عنده مقابل كامل |
| حراس مساحات الشركة (Sentry/Linear) | `~/.claude/settings.json` على جهاز كل مستخدم → hook بيمنع أي نداء MCP فيه اسم مساحة الشركة | **كود منكتبه** (مرة لكل جهاز) | Claude فقط |

# 2. الـ Multi-Agent Development والشغل المحلي

## شو بتحكي

"بعد ما الـ AI صار يعرف ومحدود — منطلق اللقطة الكبيرة: **كذا agent بنفس الوقت على نفس الـ repo**. ثلاث قواعد بتخليها آمنة: **العزل** — كل agent بنسخة معزولة على نفس الجهاز (git worktree: نسخة ثانية بمجلد منفصل وbranch منفصل، بدون clone) — مجلدك الرئيسي والـ editor ما بينلمسوا. **التقسيم بالملفات** — ولا مهمتين بيلمسوا نفس الملف، فالدمج بصفر conflicts بالتصميم — وهالقاعدة مش بذاكرتنا: مكتوبة كإجراء والـ AI نفسه بيرفض يخالفها. **والـ orchestrator** — جلسة وحدة بتوزع وبتستنى وبتدمج وبتنظف. المحصلة: خمس مهام بوقت أطول وحدة فيهم. وكل الشغل محلي — الوحيد اللي بيطلع من الجهاز هو الـ Pull Request."

## وين بينعرف

| الشي | الملف/المكان بالضبط | by default ولا منكتبه؟ | الأحسن النا |
|---|---|---|---|
| النسخ المعزولة (worktrees) | ميزة git نفسها: `git worktree add ../wt/task-a -b task/a` | **by default** — موجودة بأي git، ولا سطر كود | **الاثنين** — Claude sessions وCursor windows/background agents بيشتغلوا عليها |
| منع خلط الـ agents عنفس الملفات | **skill منكتبها**: `.claude/skills/parallel-tasks/SKILL.md` بالـ repo — فيها السياسة صراحةً: "افحص تقاطع الملفات؛ تقاطع = ممنوع توازي، اعرض تسلسل" | **كود/markdown منكتبه مرة وحدة** — وبينلجن فبيلتزم فيه كل agent | **Claude** (الـ skills آليته) — مستخدم Cursor بيستفيد من نفس القاعدة إذا انحطت بالـ rules |
| الـ orchestrator (المايسترو) | مش ملف — **جلسة Claude بتفعّل الـ skill** أعلاه؛ أدوات الإطلاق المتوازي مدمجة فيه | التوازي by default عند Claude؛ السياسة منكتبها | **Claude** — أقوى orchestration؛ Cursor بديله background agents (أبسط) |
| استرجاع أي خراب | git نفسه: `git restore` / `revert` / `branch checkpoint` | **by default** | الاثنين |

# 3. الإشارات والإجراءات: Sentry، Linear، Skills

## شو بتحكي

"الـ AI موصول بأدواتنا عبر موصل موحد اسمه **MCP** — متل USB-C: بروتوكول واحد لكل الخدمات، وبيحكيه Claude وCursor الاثنين. من **Sentry**: أول ما crash يوصل، الـ AI بيقرأ الـ stack trace، بيفتح الكود، بيوصل للسطر المذنب، بيجهز الإصلاح كـ PR، وبيسكر البلاغ. من **Linear**: موظف بيوصف مشكلة بالعامية والـ AI بيحولها ticket منسقة بمعايير الفريق وبينشئها فعلياً؛ والتذاكر الجديدة بتنفرز لحالها — أولوية وتصنيف وربط المكررات حتى عبر اللغتين. و**الـ Skills**: إجراءات الفريق مكتوبة مرة وحدة والسياسات مخبوزة جواها — طلبت تحط حل بالتذكرة؟ الـ skill نفسها بترفض، لأنه سياسة الفريق problem-only. **معرفة الفريق بتنتقل من روس الناس لملفات ملجونة كل agent بيطيعها.**"

## وين بينعرف

| الشي | الملف/المكان بالضبط | by default ولا منكتبه؟ | الأحسن النا |
|---|---|---|---|
| ربط Sentry | أمر مرة وحدة: `claude mcp add -s user --transport http sentry https://mcp.sentry.dev/mcp` + مصادقة OAuth — بينخزن بـ `~/.claude.json` | **إعداد مرة وحدة** — السيرفر جاهز من Sentry رسمياً | الاثنين بيدعموا MCP — **الأتمتة عليه Claude** |
| ربط Linear | نفس الشي: `claude mcp add -s user --transport http linear https://mcp.linear.app/mcp` | إعداد مرة وحدة | ↑ |
| مشاركة الربط مع الفريق | ملف `.mcp.json` بجذر الـ repo (بيعرّف السيرفرات للكل — كل واحد بيصادق بحسابه) | **منكتبه** — سطور JSON | الاثنين |
| skill التذاكر | `.claude/skills/linear-ticket/SKILL.md` + `template.md` بالـ repo | **منكتبها** — إجراء + قالب + سياسة problem-only | Claude |
| skill الفرز (triage) | `.claude/skills/linear-triage/SKILL.md` — سلّم الأولويات + تعليق تدقيق إلزامي + ممنوع الإغلاق | **منكتبها** | Claude |

# 4. مراحل الفحص: Integration Tests ← GitHub Actions ← Firebase Test Lab

"الفحص بثلاث مراحل بترتيب الكلفة — والمبدأ الاقتصادي: **الـ AI بيكتب الفحص مرة وحدة من وصف بالعامية** — الجزء الغالي اللي الفرق بتأجله سنين — **وأدوات مجانية حتمية بتشغله للأبد**. أولاً **Integration tests**: رحلة المستخدم ككود — يفتح، يتصفح، يحجز، يتأكد. ثانياً **GitHub Actions** — المشغّل والبواب: على كل PR فحوصات + مراجعة AI والدمج مقفول لحد ما تخضرّ؛ وكل ليلة الرحلات كاملة على iOS وAndroid بتقرير لكل منصة. ثالثاً **Firebase Test Lab**: أسبوعياً نفس الفحوصات على أجهزة **فيزيائية حقيقية** — Pixel وSamsung عند Google — بتقرير وفيديو لكل جهاز. وكله **بدون منصة QA خارجية مدفوعة**: الإطار من Flutter، المشغل GitHub، ومعرض الأجهزة بحصة مجانية."

## وين بينعرف

| الشي | الملف/المكان بالضبط | by default ولا منكتبه؟ | الأحسن النا |

| فحوصات الرحلات | مجلد `integration_test/` جوا الـ app — ملفات Dart | **الـ AI بيكتبها** من وصفنا، إحنا منراجع التغطية | إطار الفحص **جزء من Flutter** — مجاني |

# 6. يوم الموظف — كيف الشغل بيمشي فعلياً

## شو بتحكي

"الصبح بتاخد ticket من Linear — واصلة **مفروزة أصلاً**. بتفتح Cursor أو جلسة Claude — **القوانين والحراس بينشحنوا لحالهم من الـ repo**، مش عليك تتذكر شي. بتوصف الشغل — والغامض بيرجعلك **أسئلة** مش تخمينات: انت بتقرر وقراراتك بتصير الـ spec. الـ agents بينفذوا بنسخ معزولة — بالتوازي إذا المهام بتسمح. PR واحد بيطلع، بيمرق عالبوابات لحاله، انت بتراجع وبتدمج — **والـ ticket بتسكر حالها**. شغلة الموظف طلعت لفوق: من كتابة كل سطر — للقرار والمراجعة."

## وين بينعرف

كل القطع معرّفة بالأقسام السابقة — هاد القسم بس بيركّبها. الشي الوحيد الجديد: **ربط الـ ticket بالـ PR** بيصير جوا الأنبوب نفسه (الـ AI بيعلق على الـ ticket برابط الشغل وبينقل حالتها) — سياسة بنحطها بالـ skill، مش أداة إضافية.

# 8. الحلقة الكاملة: Error بـ Sentry → Ticket بـ Linear → PR على GitHub

## شو بتحكي

"وهاي اللقطة اللي بتجمع كل شي: crash بيصير عند مستخدم الساعة 3 الفجر. Sentry بيلمه، وقاعدة تنبيه بتبعت webhook لسيرفرنا. المستمع بيطلق أنبوب واحد بيعمل بالترتيب: بيسحب تفاصيل الـ issue، **بينشئ ticket بـ Linear** فيها الوصف ورابط الـ Sentry issue وأولوية حسب سلم الفرز، بيحقق بالكود وبيلاقي السطر المذنب، بيصلّح على branch، بيشغل الفحوصات، بيدفع وبيفتح **PR** موصوف كامل، بيعلق عالـ ticket برابط الـ PR وبينقلها In Review. بوابات الـ PR بتشتغل لحالها. الصبح، المهندس بيلاقي: ticket موثقة، وPR جاهز مراجَع من الـ AI — بيقرأ الـ diff وبيكبس Merge. ولما يدمج — webhook من GitHub بيسكّر الحلقة: الـ ticket بتصير Done والـ issue بـ Sentry بتصير Resolved. **من الـ crash للـ PR: صفر إيدين. الإيد الوحيدة: كبسة الدمج.**"

## وين بينعرف

| الخطوة | وين بالضبط | مين بيكتبها |
|---|---|---|
| Sentry → webhook | Sentry UI: Alerts → New Alert Rule → action: webhook لعنوان السيرفر | إعداد مرة وحدة |
| المستمع | سكربت على سيرفر AWS (~70 سطر — نموذج جاهز بالمختبر) | كود منكتبه |
| الأنبوب | `scripts/sentry_to_pr.sh` بالريبو: أمر `claude -p` واحد + `--allowedTools "mcp__sentry__*,mcp__linear__*,Read,Grep,Edit,Bash(git *),Bash(gh pr create:*)"` | كود منكتبه — مقاطعه مجربة (موديولات 04+05) |
| فتح الـ PR من السيرفر | `gh` CLI بمصادقة bot / GitHub App | إعداد مرة وحدة |
| الإغلاق عند الدمج | GitHub → Settings → Webhooks → event: pull_request → أنبوب صغير: ticket → Done + issue → Resolved | كود منكتبه (سطور) |

**ملاحظة صراحة للعرض:** مقاطع السلسلة كلها مجربة عنا — Sentry→PR بأمر واحد، وLinear→spec→تنفيذ→تحديث الـ ticket — والوصل النهائي عبر الـ webhooks هو شغل المرحلة هـ (بده السيرفر).
