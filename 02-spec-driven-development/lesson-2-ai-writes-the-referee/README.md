# الدرس 2: الـ AI بيكتب الحكم — وانت بتراجع الحكم

## 🗣️ بالعامية

بدرس 1 اكتشفت (بإيدك!) حقيقتين: الفحوصات نفسها spec قابلة للتنفيذ، والحكم قوي على قد تغطيته. طيب بالدنيا الحقيقية — **مين بيكتب الحكم؟** بدرس 1 أنا كتبتلك ياه جاهز. بس بالشغل الفعلي ما حدا رح يكتبلك فاحص لكل ميزة — بدك الـ AI يكتبه.

لحظة... الـ AI بيكتب الكود **و**بيكتب الفاحص اللي بيحكم على كوده؟ 🤨 مش هيك بيصير "الطالب بيصحح امتحانه"؟

**لأ — إذا قلبنا الترتيب.** هون سر الدرس كله:

1. **أول شي** الـ AI بيكتب الفحوصات من الـ spec — قبل ما يكتب ولا سطر كود
2. **انت بتراجع الفحوصات** — مش الكود! بتقارن كل فحص مع جدول الـ AC: كل سطر بالعقد إله فحص؟ الحدود مغطاة؟ (تذكر ثغرة الصفر!)
3. **بعد ما توقّع عالفحوصات**، الـ AI بينفذ الكود لحد ما الكل يمرق

ليش هيك أذكى؟ لأنه مراجعة 10 فحوصات مكتوبة بالإنجليزي الواضح ("سيارة ببلاش لازم ترمي خطأ") **أسهل وأأمن بكثير** من مراجعة 50 سطر كود منطق. انت بتحرس العقد، والفحوصات بتحرس الكود. هرم حراسة 🏛️

## 🔧 بالتقني

هاد الأسلوب اسمه الحقيقي **TDD (Test-Driven Development)** — بس بنسخة الـ AI Factory:

```
الترتيب التقليدي الخطر:          الترتيب الصح (هالدرس):
spec → كود → فحوصات ع الكود      spec → فحوصات ع الـ spec → مراجعتك → كود
        ⚠️ الفحوصات بتتفصّل               ✅ الكود بيتفصّل
           على الكود الموجود                  على الفحوصات المعتمدة
```

الفرق الجوهري: لما الفحوصات تنكتب **قبل** الكود ومن الـ spec مباشرة، الكود مجبور يلحق العقد. لما تنكتب **بعد** الكود، بتلحق الكود بأخطائه (وبتبارك الـ bugs الموجودة).

ونقطة العامل البشري: دورك انتقل من "مراجع كود" لـ **"مراجع عقود"** — أعلى بالهرم، أقل جهد، أثر أكبر. هاي نفسها فكرة الـ AI Factory: البشر عالحدود والقرارات، الـ AI عالتنفيذ.

### الخطوة 1 — الـ AI بيكتب الحكم (وممنوع يكتب كود)

> Read specs/delivery-fee.md and write tool/spec_check.dart — a standalone Dart script (like a test suite) that checks an implementation of DeliveryFee.compute against EVERY acceptance criterion and edge case in the spec. Do NOT implement lib/delivery_fee.dart yet — referee first.

### الخطوة 2 — انت بتراجع الحكم (أهم خطوة بالدرس)

افتح `tool/spec_check.dart` جنب `specs/delivery-fee.md` وراجع **كمدقق عقود**:

- [ ] كل AC من الخمسة إله فحص واحد عالأقل؟
- [ ] الحدود بالضبط: `carPrice = 50000`؟ `distanceKm = 10`؟ `distanceKm = 50` (الصيغة = الحد الأدنى)؟
- [ ] الأخطاء: صفر وسالب للاثنين؟ *(تذكر ثغرة درس 1 — الصفر هو اللي هرب!)*
- [ ] حالة "القاعدتين المجانيتين مع بعض"؟

لقيت نقص؟ **اطلب منه يضيف الفحص الناقص** — هاي بالضبط شغلتك الجديدة. (وإذا كان كامل — ممتاز، وثّق لنفسك إنك دققت)

### الخطوة 3 — هلق بس، التنفيذ

> Now implement lib/delivery_fee.dart according to the spec, and keep going until `dart tool/spec_check.dart` reports everything passing.

وتحقق بنفسك:

```bash
dart tool/spec_check.dart
```

### سؤال التثبيت

ليش منراجع الفحوصات بدل ما منراجع الكود؟ *(الجواب عايش بتجربتك بدرس 1: الكود بيقدر يخالف العقد بأي مكان الفحوصات ما بتغطيه — فاللي بيحدد الأمان الحقيقي هو تغطية الحكم، مش شكل الكود)*
