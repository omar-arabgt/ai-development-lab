# الدرس 3: المراجع الذكي — Claude على كل PR

## 🗣️ بالعامية

بوابتك هلق بتفحص **العقد**: الفاحص بيتأكد إنه `compute` بترجع الأرقام الصح. بس تخيل PR بيضيف فانكشن **جديدة** فيها قسمة على صفر محتملة، أو مفتاح API مزروع بالكود، أو منطق ملخبط — الفاحص بيطلع **أخضر** لأنه ولا AC انكسر! الحكم بيحرس العقد المكتوب بس؛ **اللي برا العقد، محدا شايفه**.

بالفرق التقليدية، هون بييجي دور المراجع البشري. المشكلة: المراجعة البشرية بطيئة، مزاجية، وأول شي بينضحى فيه وقت الضغط. الحل بالـ AI Factory: **مراجع AI بيشتغل مع كل PR أوتوماتيكياً** — بيقرأ الـ diff، بيعلّق على الأسطر المشبوهة، وما بيزهق ولا بيستعجل ولا "بيمشيها هالمرة".

هيك بيكتمل ثالوث البوابة: **الحكم** (بيفحص العقد) + **القفل** (بيمنع الأحمر) + **المراجع** (بيقرأ اللي برا العقد).

## 🔧 بالتقني

القطعة: **claude-code-action** — GitHub Action رسمي من Anthropic بيشغّل Claude Code جوا الـ runner. بيقدر يشتغل بنمطين:

1. **مراجعة تلقائية**: كل PR بينفتح → Claude بيقرأ الـ diff وبيكتب مراجعة كتعليق
2. **بالمناداة**: بتكتب `@claude` بأي تعليق على PR أو Issue → بيرد، يشرح، وحتى يصلّح ويدفع commits

### المصادقة — نقطة مهمة تفهمها صح

الـ runner بالسحابة بده يحكي مع حساب Claude تبعك. الطريقة: **token** بينخزن بـ **GitHub Secrets** — خزنة مشفرة بإعدادات الريبو، الـ workflow بيقرأ منها بصيغة `${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}`. **ولا سر بينكتب بالكود أبداً** — تذكر درس Permissions لما منعنا قراءة الـ secrets؟ نفس الفلسفة، نسخة GitHub.

## 🧪 التجربة

### 1. التنصيب (مرة وحدة — معالج جاهز)

افتح جلسة Claude Code **بجذر ريبو الـ lab** واكتب:

```
/install-github-app
```

المعالج بيمشيك خطوة خطوة: تنصيب Claude GitHub App على الريبو → توليد token من اشتراكك → تخزينه كـ secret → وبيفتح PR فيه ملفات الـ workflow. **اقرأ الـ PR اللي بيفتحه** (صرت تعرف تقرأ workflows 😎) وادمجه.

> لو المعالج خيّرك بين أنماط: فعّل الاثنين — المراجعة التلقائية (`claude-code-review.yml`) والمناداة (`claude.yml`).

### 2. حضّر PR "أخضر بس مريب" 😈

```bash
git checkout main && git pull
git checkout -b sneaky-green
```

افتح `03-pr-review-automation/lesson-1-ci-referee/playground/lib/reservation_deposit.dart` وضيف **تحت** الفانكشن الموجودة (بدون ما تلمسها):

```dart
  /// Splits the deposit across [installments] payments.
  static double perInstallment(double carPrice, int installments) {
    // TODO(review-bait): looks innocent, ships two real problems.
    final apiKey = 'sk-live-9f2c81d7'; // for the payments provider
    return compute(carPrice) / installments;
  }
```

```bash
git commit -am "Add installment splitting for deposits"
git push -u origin sneaky-green
```

افتح الـ PR وراقب **الفحصين مع بعض**:
- **CI Referee**: ✓ أخضر — العقد ما انكسر (الفانكشن الجديدة برا الـ spec كلياً!)
- **مراجعة Claude**: بتظهر كتعليق عالـ PR — والمفروض يمسك **المشكلتين المزروعتين**: مفتاح API بالكود (أمان) وقسمة على `installments` ممكن تكون صفر (منطق)

هاي اللحظة التعليمية: **أخضر ≠ سليم**. الأخضر معناه "العقد المفحوص ما انكسر" وبس.

### 3. جرب المناداة

بنفس الـ PR، اكتب تعليق:

> @claude fix the two issues you found and push the fix to this branch

وراقبه يصلّح ويدفع commit بنفسه — أول مرة بتشوف AI بيشتغل **جوا GitHub، مش جوا جهازك**.

### 4. سكّر القصة

بعد ما يصلّح وتخضرّ الفحوصات — ادمج. وامسح الفانكشن التجريبية بـ PR صغير لاحقاً إذا بدك الـ playground نظيف (أو خليها — ما بتأذي).

### سؤال التثبيت

ليش منحتاج المراجع **والحكم** مع بعض — ليش المراجع الذكي لحاله مش كفاية؟ *(فكر: شو الفرق بين فحص deterministic بيرجع نفس الجواب كل مرة، وبين مراجعة ذكية بترى أوسع بس ممكن تختلف من مرة لمرة؟ البوابة الصلبة للعقد، والعين الذكية لكل الباقي)*
