# الدرس 1: الحكم السحابي — أول بوابة على GitHub

## 🗣️ بالعامية

لحد هلق كل الحراس اللي بنيناهم بيشتغلوا **على جهازك**: الـ hook بدرس Hooks بيحرس جلستك انت، والحكم المحايد بموديول 02 بتشغله انت بإيدك. بس الفريق مش انت لحالك — شو بيمنع زميلك (أو agent مستعجل 😅) يدمج كود بيكسر العقد وهو ما شغّل الفاحص أصلاً؟

الحل: **ننقل الحكم من جهازك لبوابة المشروع نفسها** — GitHub. من هلق، أي PR بيلمس كود الميزة، GitHub **لحاله** بيشغل الفاحص على سيرفر بالسحابة: أخضر ✓ بيدخل، أحمر ✗ بيوقف عالباب — مهما كان صاحب الـ PR مستعجل، ومهما كان جهازه "شغال عنده تمام".

هاد اسمه **CI (Continuous Integration)** — وهو أول قطعة بالمصنع اللي بتشتغل **بدون ما حدا يشغلها**. لهلق كل شي كنت تطلبه انت؛ من هلق الأشياء بتصير **لأنه صار حدث** (انفتح PR) مش لأنه حدا طلب. تذكر "Event-Driven" من درس الـ Hooks؟ نفس الفكرة — بس عالسحابة وعالفريق كله.

## 🔧 بالتقني

القطعة الجديدة الوحيدة ملف واحد: `.github/workflows/ci-referee.yml` (بجذر الريبو). فكه سطر سطر:

```yaml
on:                        # المشغّل: أي حدث بيوقظ الحارس؟
  pull_request:            # → كل ما ينفتح/يتحدث PR
    paths:                 # → بس إذا لمس هالملفات
      - '03-pr-review-automation/lesson-1-ci-referee/playground/**'

jobs:
  spec-check:
    runs-on: ubuntu-latest # GitHub بيأجرنا سيرفر Linux نظيف لكل تشغيلة
    steps:
      - uses: actions/checkout@v4      # ينزّل كود الـ PR عالسيرفر
      - uses: dart-lang/setup-dart@v1  # يركّب Dart
      - run: dart .../tool/spec_check.dart  # يشغل حكمنا — حرفياً نفس الملف
```

النقطة الذهبية بالسطر الأخير: **نفس الفاحص اللي كتبناه بموديول 02، بدون أي تعديل**. الفرق الوحيد اللي أضفناه: الفاحص بيطلع بـ `exit(1)` عند الفشل — تذكر **Exit Code** من درس الـ Hooks؟ (0 = مرّق، غيره = امنع). GitHub بيقرأ نفس الرمز: exit 0 → ✓ أخضر، exit 1 → ✗ أحمر والدمج بيتقفل.

يعني السلسلة اكتملت: **العقد (spec) → الحكم (spec_check) → البوابة (CI)** — نفس الفكرة بثلاث طبقات، من ورقة مكتوبة لسور حول الريبو.

## 🎯 الـ playground

`playground/` فيه ميزة "عربون الحجز" (5% من السعر، حده الأدنى 500 وأقصاه 2000) — **جاهزة ومخضرّة من البداية** (عكس كل الدروس السابقة!). ليش؟ لأنه تمرينك مش تبنيها — تمرينك **تكسرها بـ PR وتشوف البوابة بتصده**.

## 🧪 التجربة — دورة الأحمر/الأخضر الكاملة

### 0. حدّث نسختك المحلية وتأكد إنه الحكم أخضر

```bash
cd /Users/omarabed/Documents/work/sandbox/ai-development-lab
git pull
dart 03-pr-review-automation/lesson-1-ci-referee/playground/tool/spec_check.dart
```

(لازم: `11 passed — SPEC HONORED`)

### 1. اعمل branch واكسر العقد عمداً 😈

```bash
git checkout -b break-the-contract
```

افتح `03-pr-review-automation/lesson-1-ci-referee/playground/lib/reservation_deposit.dart` وغيّر النسبة:

```dart
static const double _rate = 0.05;   →   static const double _rate = 0.07;
```

(تغيير صغير، منطقي الشكل، من النوع اللي بيمرق بمراجعة عالسريع — بس بيخالف AC1 بالعقد)

```bash
git commit -am "Adjust deposit rate"
git push -u origin break-the-contract
```

### 2. افتح PR وشوف الحارس بيصحى لحاله

افتح الرابط اللي بيطبعه git بعد الـ push (أو روح على GitHub → الريبو → "Compare & pull request") واعمل **Create pull request**.

بعد ثواني، بأسفل صفحة الـ PR بتشوف: **CI Referee / Spec contract check** عم يركض 🟡... وبعدين **✗ أحمر** — اكبس "Details" واقرأ اللوج: رح تلاقي نفس مخرجات الفاحص اللي بتعرفها (`FAIL AC1 ...`) بس هالمرة **على سيرفر GitHub، بدون ما تشغل شي**.

### 3. صلّح وشوف البوابة بتفتح

رجّع `0.05`، بعدين:

```bash
git commit -am "Restore the contracted deposit rate"
git push
```

ارجع لصفحة الـ PR — الفحص بيعيد حاله **لحاله** (الحدث: تحديث الـ PR) وبيصير **✓ أخضر**. هلق ادمجه بضمير مرتاح: **Merge pull request** (صافي التغيير صفر — كسرنا ورجعنا).

### سؤال التثبيت

الفاحص نفسه ما تغير ولا سطر من موديول 02 — شو اللي تغير جوهرياً إذاً؟ *(تلميح: مين بيقرر إنه الفاحص يركض — ووين)*
