# الدرس 2: القفل — Branch Protection

## 🗣️ بالعامية

بدرس 1 صار موقف ذهبي: الفحص طلع **أحمر ✗**... وGitHub خلاك تدمج عادي 😄. ليش؟ لأنه الـ Status Check لحاله **إشارة** — متل لمبة حمرا عالتقاطع بدون كاميرا ولا شرطي: اللي مستعجل بيمرق.

هالدرس منركّب الكاميرا: **Branch Protection** بيحوّل الإشارة لقفل — الفرع `main` بيصير محمي، وزر الدمج **بينقفل فعلياً** لحد ما الفحص يخضرّ. مش أدب ولا اتفاق فريق — GitHub نفسه بيرفض.

لاحظ النمط اللي عم يتكرر بكل المختبر:
- **Permissions** (موديول 00): شو مسموح للـ AI — قانون مش رجاء
- **Hooks**: exit 2 بيمنع العملية — قانون مش رجاء
- **Skill الـ parallel-tasks**: بيرفض التوازي عنفس الملف — سياسة مخبوزة
- **Branch Protection**: الأحمر بيمنع الدمج — قانون مش رجاء

كلها نفس الفلسفة: **القوانين المهمة بتنحفر بالنظام، ما بتنحفظ بالذاكرة.**

## 🔧 بالتقني

الحماية بتنضبط من إعدادات الريبو على GitHub (مش ملف بالكود — هي سياسة عالسيرفر نفسه). العناصر اللي منفعّلها:

| الإعداد | شو بيعمل |
|---|---|
| **Require status checks to pass** | زر الدمج مقفول لحد ما الفحوصات المحددة تخضرّ |
| اختيار `Spec contract check` | تحديد **أي** فحص هو الشرط (فحص درس 1 تبعنا) |
| **Require a pull request before merging** *(اختياري)* | ممنوع الدفع المباشر لـ main — كل شي عبر PR |

> ⚠️ **شرط مسبق:** على حسابات GitHub المجانية، الـ Branch Protection بيشتغل على الريبوهات **العامة (public)** بس — الخاصة بدها خطة Pro. الـ lab ريبو تعليمي بدون أي كود شركة، فتحويله public خيار منطقي — بس القرار قرار صاحبه.

## 🧪 التجربة

### 1. فعّل الحماية (مرة وحدة، من المتصفح)

1. افتح الريبو على GitHub → **Settings** → **Branches** (بالقائمة الجانبية)
2. تحت "Branch protection rules" اكبس **Add rule** (أو Add classic branch protection rule)
3. بخانة "Branch name pattern" اكتب: `main`
4. فعّل ☑️ **Require status checks to pass before merging**
5. بصندوق البحث اللي بيظهر، دوّر على **`Spec contract check`** واختاره
6. *(اختياري بس منصوح فيه)* فعّل ☑️ **Require a pull request before merging**
7. **Create** / **Save changes**

### 2. أعد سيناريو درس 1 — وشوف الفرق

```bash
cd /Users/omarabed/Documents/work/sandbox/ai-development-lab
git checkout main && git pull
git checkout -b break-again
```

غيّر `_rate` لـ `0.07` (نفس كسرة درس 1)، بعدين:

```bash
git commit -am "Try to sneak a rate change"
git push -u origin break-again
```

افتح PR → استنى الفحص يطلع **✗ أحمر** → وهلق التفرج: **زر الدمج رمادي مقفول** 🔒 مع رسالة "Required statuses must pass". جرب تكبسه — ما في. هاي اللي كانت ناقصة بدرس 1.

### 3. صلّح وافتح القفل

رجّع `0.05` (وخلي التعليق فوقها زي ما هو — عبرة الفرق الصافي من درس 1 😉)، commit وpush → الفحص بيخضرّ → **الزر بيفتح لحاله** → Merge.

### 4. بونص: جرب تدفع لـ main مباشرة

إذا فعّلت "Require a pull request"، جرب من branch main مباشرة:

```bash
git checkout main
# عدّل أي ملف بالـ playground، اعمل commit، وبعدين:
git push
```

GitHub بيرفض الدفعة نفسها — حتى صاحب الريبو بيمر عالبوابة. (بعد التجربة رجّع تعديلك بـ `git reset --hard origin/main`)

### سؤال التثبيت

بالشركة، مين المفروض يقدر يعمل "bypass" للحماية — وهل المفروض حدا يقدر أصلاً؟ *(ما إله جواب واحد صح — بس فكر: كل استثناء بتفتحه اليوم، هو الباب اللي رح يخرب منه شي بكرة. وبالـ AI Factory تحديداً: الـ agents بيدفعوا PRs — القفل هو الضمانة إنه ولا سطر AI بيفوت بدون ما يمرق عالحكم)*
