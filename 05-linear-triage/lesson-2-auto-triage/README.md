# الدرس 2: الفرّاز — triage أوتوماتيكي للتذاكر

## 🗣️ بالعامية

صندوق التذاكر الجديد بأي شركة متل بريد الصبح: عناوين ضبابية ("التطبيق خربان!!")، أولويات مش محطوطة، خلطة بين bugs وطلبات ميزات وأسئلة، وشغلات مكررة. حدا لازم **يفرز**: يعدّل العناوين، يصنّف، يحط أولويات، يمسك المكرر — شغل ضروري وممل وبياكل أول ساعة من يوم شخص كل يوم.

هالدرس منبني **الفرّاز**: skill بتمشي على كل التذاكر غير المفروزة وبتعمل الفرز كامل — **مع تعليق بيشرح منطقها على كل تذكرة** عشان الفريق يقدر يدقق قراراتها. والقاعدة الذهبية مخبوزة فيها: **الفرّاز بينظم، البشر بيقرروا** — ممنوع يسكّر أو يحذف أي تذكرة، مهما كان متأكد.

## 🔧 بالتقني

افتح `SKILL.md` وشوف الهيكل — القيمة الحقيقية بثلاث قطع:

1. **الـ rubric (سلّم الأولويات):** معايير مكتوبة صريحة — "Urgent بس للـ crashes وفقدان البيانات والدفع والأمان، **ممنوع تخمين Urgent من كلام ضبابي**". بدون rubric مكتوب، كل تشغيلة بتجتهد غير اجتهاد
2. **التعليق الإلزامي:** كل قرار triage بيترك أثر مكتوب قابل للتدقيق — نفس فلسفة "الحكم المحايد": القرار الشفاف بينراجع، الصامت بينساق
3. **حدود صلاحيات صريحة:** عناوين/labels/أولويات/تعليقات بس — لا إغلاق، لا حذف، لا تعديل وصف
