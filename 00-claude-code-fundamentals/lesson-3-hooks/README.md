# الدرس 3: Hooks — الحرّاس اللي بتكتبهم بإيدك

## 🗣️ بالعامية

بالدرس 2، الـ Permissions كانت متل **أقفال جاهزة من المصنع**: بتحدد نمط ("ممنوع `cat`") وخلص. قوية، بس غبية شوي — بتفهم أنماط بس، ما بتفهم منطق.

طيب شو لو بدك قانون متل: *"أي أمر فيه كلمة production — بأي شكل، بأي أداة، بأي صياغة — ارفضه"*؟ أو: *"بعد كل تعديل على ملف كود، افحصه، وإذا فيه مشاكل رجّع الـ AI يصلحها"*؟

هاد بدو **حارس حي مش قفل** — حارس بيوقف عالباب، بيفتش كل طلب، وبيقرر حسب **تعليمات انت كاتبها بكود**. هاد هو الـ Hook: **سكربت من كتابتك، النظام بينفذه أوتوماتيك عند حدث معين، وإله سلطة يمنع**.

والجملة الأهم بالدرس كله: **الحارس مش AI. الحارس كود عادي.** ما بينسى، ما بينقنع، ما بيتعب. بينفذ حرفياً كل مرة.

## 🔧 بالتقني

الـ Hook بيتسجل بـ `.claude/settings.json` وبيرتبط بـ **حدث (event)**:

| الحدث | إيمتى بينفذ | استخدامه الكلاسيكي |
|---|---|---|
| `PreToolUse` | **قبل** تنفيذ أي أداة | فحص ومنع (الحارس) |
| `PostToolUse` | **بعد** نجاح الأداة | فحص جودة، lint، تنبيهات |
| `UserPromptSubmit` | لما تبعت رسالة | إضافة سياق، فلترة |
| `Stop` | لما الـ AI يخلص رده | إشعارات، تقارير |
| `SessionStart` | بداية الجلسة | تحضير البيئة |

### كيف بيحكي النظام مع الحارس؟ (البروتوكول)

```
النظام ──(JSON فيه تفاصيل العملية عبر stdin)──► السكربت تبعك
السكربت بيرد بـ exit code:
  0 ← "مرّق" (وإذا PostToolUse: كله تمام)
  2 ← "امنع!" — وكل شي مكتوب على stderr بيرجع للـ AI كتغذية راجعة
```

يعني السكربت بيستلم مثلاً:
```json
{"tool_name": "Bash", "tool_input": {"command": "echo deploying to production"}}
```
وبيقرر: طلع `exit 0` (مرّق) أو `exit 2` (ممنوع + السبب على stderr).

### حارسين الـ playground

**1) `block-production.sh` — حارس المنع (PreToolUse على Bash):**
```bash
input=$(cat)                          # receive the JSON
if echo "$input" | grep -qiE 'production|prod-db|prod\.'; then
  echo "🚫 Blocked: production reference detected" >&2
  exit 2                              # block + reason goes back to the AI
fi
exit 0
```
لاحظ الفرق عن Permissions: مش نمط أمر — **فحص محتوى**. كلمة production وين ما كانت، بأي أمر، بتنمسك.

**2) `quality-gate.sh` — بوابة الجودة (PostToolUse على Edit/Write):**
بعد كل تعديل ملف dart → بيشغل `dart analyze` → إذا في مشاكل بيرجع `exit 2` مع تقرير المشاكل → **الـ AI بيشوف التقرير وبيصلح لحاله**. هاد أول self-healing loop منبنيه: غلطة → فحص أوتوماتيك → تصليح أوتوماتيك.

## 🧪 التجربة

افتح جلسة بالـ playground وجرب بالترتيب:

| # | اطلب | شو المفروض يصير |
|---|---|---|
| 1 | "شغّل الأمر: echo 'starting deploy to production server'" | ❌ الحارس بيمسكه — مع إنه `echo` بريء تماماً وما في ولا قانون permissions ضده. **الكلمة** انمسكت، مش الأمر |
| 2 | "شغّل الأمر: echo hello" | ✅ بيمر عادي (بعد سؤال ask العادي) — الحارس فحصه ومرّقه |
| 3 | "ضيف بـ lib/main.dart متغير اسمه x بدون ما تستخدمه — تجربة مقصودة" | 🔄 بيعدّل → بوابة الجودة بتشتغل → بتلاقي المشكلة → بترجعله التقرير → **بيصلحها لحاله**. راقب هاد بعينك |

## 💡 ليش هاد الدرس هو المفتاح لكل الأتمتة الجاية؟

لأنه الـ Hook هو **أصغر وحدة "نظام بيراقب AI"**. كل الموديولات الجاية هي نفس الفكرة مكبّرة:
- Sentry Auto-Fix = حدث (bug جديد) → كود بيشغل AI → بوابة جودة قبل الـ PR
- QA أوتوماتيك = حدث (كل صباح) → AI بيفحص → تقرير
- الحماية بموديول 08 = نفس حارس production تبعنا، بنسخة أقوى

فهمت الـ Hook؟ فهمت كل شي جاي.

## 🏢 كيف تنقلها لمشاريع الشركة

1. **حارس production** (نفس تبعنا مع توسيع الكلمات: أسماء سيرفراتكم، database URLs، `firebase deploy`, `fastlane release`...)
2. **بوابة جودة Flutter**: بعد كل تعديل → `dart format` + `flutter analyze` — بيضمن إنه ولا سطر كود من الـ AI بيدخل بدون فحص
3. **إشعار Slack عند نهاية كل مهمة** (Stop hook) — الفريق بيشوف شو عمل الـ AI أول بأول

> ⚠️ ملاحظة أمانة علمية: حارسنا بيفحص بـ grep بسيط — للديمو ممتاز، بس بالشركة منكتبه أذكى (jq لتحليل الـ JSON، قوائم كلمات أشمل، فحص فعلي للـ hosts). الفكرة نفسها، التنفيذ أمتن.
