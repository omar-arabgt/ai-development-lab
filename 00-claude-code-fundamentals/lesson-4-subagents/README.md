# الدرس 4: Subagents — الموظفين المتخصصين

## 🗣️ بالعامية

لحد هلأ كنت بتشتغل مع **موظف واحد شاطر بكل شي**. بس الشركات الحقيقية ما بتشتغل هيك — في مراجع كود، وفاحص أمان، ومهندس QA. كل واحد **متخصص**، وكل واحد **بصلاحيات مختلفة**: مراجع الكود بيقرأ وما بيعدّل، والمحاسب بيوصل للفواتير وما بيوصل للسيرفرات.

الـ Subagent هو بالضبط هيك: **موظف بتوظفه انت، بتكتبله وصف وظيفته بملف، وبتحدد شو الأدوات المسموحة إله**. ولما يجي شغل من تخصصه — المدير العام (الجلسة الرئيسية) **بيفوضله المهمة**، الموظف بيشتغلها بمكتبه الخاص، وبيرجع بتقرير نهائي.

وليش "مكتبه الخاص" مهمة؟ لأنه لما موظف يقرأ 50 ملف عشان يراجعهم، كل هالقراءة **ما بتلوث ذاكرة المدير** — المدير بيوصله التقرير النظيف بس. 

## 🔧 بالتقني

الـ Subagent = **ملف markdown** بمجلد `.claude/agents/` بالمشروع (أو `~/.claude/agents/` لكل مشاريعك):

```markdown
---
name: code-reviewer
description: Reviews code quality after changes. Read-only, never edits.
tools: Read, Grep, Glob
---
You are a senior code reviewer...        ← هاد الـ system prompt تبعه
```

| الحقل | شو بيعمل |
|---|---|
| `name` | اسمه — بتناديه فيه |
| `description` | **مهم جداً**: المدير بيقرأه ليقرر إيمتى يفوضله شغل أوتوماتيك |
| `tools` | قائمة الأدوات المسموحة — **ما ذكرته = ممنوع عليه**. مراجع بدون Edit = مستحيل يعدّل |
| النص تحت | شخصيته وتعليماته — بتحدد كيف بيفكر وشو شكل تقاريره |

### شو بيصير بالكواليس لما يشتغل؟

```
المدير (جلستك) ──"راجعلي الكود"──► subagent بينطلق
                                    │ context window جديدة فاضية (مكتبه الخاص)
                                    │ بيقرأ، بيدور، بيحلل (خطواته ما بتظهر عندك)
                                    ◄──بيرجع تقرير نهائي واحد──
المدير بيكمل شغله والتقرير بإيده — وذاكرته نظيفة
```

نقطتين قوة:
1. **عزل السياق (Context Isolation):** شغل الموظف الداخلي ما بياكل من ذاكرة جلستك
2. **عزل الصلاحيات:** الأدوات بتنحدد **بالتعريف** — مش "أدب"، الموظف بدون Edit تقنياً ما معه المفتاح (متل درس Permissions، hard enforcement)

## 👥 موظفين الـ playground

1. **`code-reviewer`** — مراجع كود: بيفحص الجودة (تسمية، منطق، أخطاء محتملة). أدواته: قراءة وبحث بس
2. **`security-auditor`** — مدقق أمان: بيدور على أسرار مزروعة بالكود، مخاطر أمنية. برضو قراءة بس

وحطينا بـ `lib/price_service.dart` **4 مشاكل مزروعة عمداً**: مفتاح API مكتوب بالكود، قسمة ممكن تكون على صفر، متغير مهمل، وبعثرة `print` — كل موظف رح يمسك اللي من تخصصه.

## 🧪 التجربة

افتح جلسة بالـ playground وجرب بالترتيب:

| # | اطلب | شو بتتعلم |
|---|---|---|
| 1 | "Use the code-reviewer agent to review lib/price_service.dart" | بتشوف التفويض: بينطلق، بيشتغل بمعزل، بيرجع تقرير |
| 2 | "Ask the security-auditor to scan the same file" | موظف ثاني، تخصص ثاني — بيمسك الـ API key اللي المراجع ممكن ما ركز عليه |
| 3 | "Run both agents at the same time on lib/" | 🚀 **بيشتغلوا بالتوازي** — أول لمحة من موديول 01 |
| 4 | اطلب من الـ code-reviewer إنه **يصلّح** المشاكل اللي لقاها | بيعتذر أو بيرجعها للمدير — **ما معه أداة Edit أصلاً**. عزل الصلاحيات قدام عينك |

## 🏢 كيف تنقلها لمشاريع الشركة

فريق جاهز تعمله بريبو الـ Flutter من يوم واحد:
- `flutter-reviewer` — مراجع بيعرف قوانين الـ linting تبعكم (قراءة بس)
- `test-writer` — بيكتب unit/widget tests بس (Edit على مجلد `test/` نظرياً عبر التعليمات + hooks للتشديد)
- `l10n-checker` — بيفحص ملفات الترجمة العربية/الإنجليزية عن نقص أو تعارض (مشكلة المتجر اللي انحكت بالميتنغ!)
- `pr-describer` — بيقرأ الـ diff وبيكتب وصف الـ PR

والصورة الكبيرة: هدول نفسهم بيصيروا عمال الـ AI Factory بالموديولات الجاية — نفس الملفات، بس بدل ما انت تناديهم، الأتمتة بتناديهم.
