# الدرس 1: الجرس — الحدث بيدق والأنبوب بيصحى

## 🗣️ بالعامية

راجع رحلة موديول Sentry: بالبداية **انت** سألت عن الخطأ، بعدين **انت** كتبت أمر الأنبوب. بكل الحالات، الشرارة كانت **إصبعك**. هالدرس منقلب الاتجاه نهائياً: **الحدث نفسه بيدق الجرس** — Sentry بيقول "في خطأ جديد!"، والجرس بيصحّي الأنبوب، والأنبوب بيشتغل — **وانت مش موجود بالمشهد أصلاً.**

هاد هو الـ **webhook**: بدل ما تسأل الخدمة كل شوي "في جديد؟" (متل ولد بيسأل "وصلنا؟" كل دقيقة 😄)، بتعطيها **عنوان** وبتقلها: "لما يصير شي، دقيلي هون". آخر قطعة ناقصة من الـ AI Factory — الزناد.

## 🔧 بالتقني

```
Sentry (حدث جديد) ──POST──►  المستمع (سيرفر HTTP صغير)  ──بيشغّل──►  claude -p (الأنبوب)
                             "الجرس"                                    وبيكتب التقرير/الإصلاح
```

- **المستمع**: سيرفر Dart بـ 70 سطر (اقرأه — بسيط عمداً) بيسمع على `localhost:8787`. أي POST على `/sentry-alert` فيه `issue_id` → بيطلق `claude -p` بالـ headless mode مع `--allowedTools` مشدودة (كل دروس القائمة الصح معنا لهون)
- **بالمختبر منحاكي الحدث بـ `curl`** — نفس الـ POST اللي Sentry الحقيقي بيبعته. ليش المحاكاة؟ لأنه Sentry السحابي بده يوصل لجهازك — وجهازك مش معروض عالإنترنت. بالشركة، المستمع بيسكن على سيرفر/cloud function بعنوان عام وSentry بيدقله مباشرة (وللتجارب في أدوات متل ngrok بتفتح نفق مؤقت — منحكي عنها بجلسة النقل)

## 🧪 التجربة — تيرمينالين وجرس

### تيرمينال 1 — سلّح الجرس

```bash
cd /Users/omarabed/Documents/work/sandbox/ai-development-lab/09-automation-infra/lesson-1-webhooks/playground
dart run bin/webhook_listener.dart
```

(لازم: "Doorbell armed" — وخليه شغال. للفحص السريع بدون تشغيل الأنبوب فعلياً في وضع `DRY_RUN=1`)

### تيرمينال 2 — انت هلق بتلعب دور Sentry

```bash
curl -X POST localhost:8787/sentry-alert -H 'Content-Type: application/json' -d '{"issue_id":"FLUTTER-TEST-2","title":"Unparseable branch count"}'
```

### وهلق ارجع للتيرمينال 1 واتفرج 🍿

🔔 الجرس دق → ⚙️ الأنبوب صحي → بيسحب تفاصيل الـ issue من Sentry، بيحقق بالكود، وبيكتب `reports/webhook-FLUTTER-TEST-2.md` — **تشخيص كامل ولا كبسة من إيدك بعد الـ curl**. اقرأ التقرير:

```bash
cat reports/webhook-*.md
```

### سؤال التثبيت

الـ curl هون بيمثل دور Sentry — يعني عملياً: **أي نظام بيعرف يبعت POST صار يقدر يصحّي مصنعك**. عدد 3 أنظمة من بيئة شغلكم الحقيقية ممكن تكون "جرس"، وشو بيصير لما يدقوا؟ *(أمثلة للإلهام: Sentry عند crash جديد، Linear عند تذكرة بعمود معين، GitHub عند فتح PR... — لاحظ إنك بنيت الأنابيب الثلاثة أصلاً!)*

## 🏢 كيف تنقلها لمشاريع الشركة

*(للمستقبل — بجلسة النقل المخصصة)*

Sentry وLinear وGitHub كلهم بيدعموا webhooks من إعداداتهم (Settings → Webhooks → حط العنوان). المستمع بيصير خدمة صغيرة على سيرفر الشركة (أو GitHub Actions كمستمع جاهز — تذكر `on: pull_request`؟ **هاد webhook متنكر** — GitHub بنى الجرس والمستمع سوا وانت بس كتبت الوصفة). درسنا الجاي: الأحداث المجدولة — مش "لما يصير شي" بل "كل يوم الساعة 7".
