# الدرس 1: عيون على الإنتاج — ربط Sentry

## 🗣️ بالعامية

Sentry هو **جهاز إنذار الحريق** تبع التطبيق: أي crash بيصير عند أي مستخدم — بالليل، بالسيارة، بجهاز ما شفته بحياتك — بيوصلك تقرير كامل: شو انكسر، بأي سطر، عند قديش مستخدم، وعلى أي نظام. (عندكم بالشركة أصلاً — هاد الدرس بيفهمك شو صار جواه).

اللي منعمله بهالموديول عالمراحل: **الدرس 1 (اليوم): منعطي الـ AI عيون** — يقدر يقرأ أخطاء Sentry بنفسه من جوا جلستك. الدرس 2: يشخّص. الدرس 3: يصلّح ويفتح PR لحاله. بالنهاية: الدورة اللي انحكت بالميتنغ — bug بيوصل، AI بيحلله وبيصلحه.

وكيف الـ AI "بيشوف" Sentry؟ عبر **MCP** — البروتوكول اللي بيوصّل الـ AI بأدوات خارجية. فكّرها متل شاحن الـ USB-C: معيار واحد، بتوصل فيه أي جهاز — Sentry اليوم، Linear بالموديول الجاي، ونفس الفكرة لأي خدمة.

## 🔧 بالتقني

| مصطلح | يعني شو |
|---|---|
| **DSN** | عنوان "صندوق البريد" تبع مشروعك بـ Sentry — التطبيق بيبعتله التقارير. مش سر خطير، بس عادة منحطه بـ env variable |
| **Event** | تقرير crash واحد (خطأ + stack trace + بيئة + جهاز) |
| **Issue** | مجموعة events متشابهة مجمعين — "هاد الخطأ صار 1,432 مرة عند 89 مستخدم" |
| **Sentry MCP** | سيرفر رسمي من Sentry (mcp.sentry.dev) بيعطي الـ AI أدوات: عرض issues، تفاصيل، بحث — بمصادقة OAuth من حسابك |

## 🎯 الـ playground

سكربت Dart بيمثّل "الوظيفة الليلية" اللي بتستورد إعلانات السيارات من فيد الوكيل — وواحد من الإعلانات سعره بصيغة مكسورة (`"12,500 JOD"`) → crash حقيقي بينبعت لـ Sentry. هاد الخطأ هو "الجثة" اللي رح يشتغل عليها التحقيق بدروس 2 و3 😄

## 🧪 التجربة

### 0. جهّز حساب Sentry (مرة وحدة — 5 دقائق)

> ⚠️ **مهم:** حساب **شخصي مجاني جديد** — مش حساب الشركة! (production خط أحمر، والمختبر بيلعب بحسابه الخاص بس)

1. سجل على sentry.io (الخطة المجانية كافية وزيادة)
2. أنشئ مشروع جديد → اختار المنصة: **Dart**
3. من إعدادات المشروع انسخ الـ **DSN** (بيبلش بـ `https://...@....ingest...sentry.io/...`)

### 1. فجّر الخطأ وابعته لـ Sentry

```bash
cd /Users/omarabed/Documents/work/sandbox/ai-development-lab/04-sentry-autofix/lesson-1-sentry-eyes/playground
dart pub get
export SENTRY_DSN="الصق-الـDSN-هون"
dart run bin/import_listings.dart
```

لازم تشوف: أول سيارتين انستوردوا، والثالثة كسرت السكربت — مع رسالة إنه الخطأ انبعت. افتح Sentry بالمتصفح → **Issues** → بتلاقي `FormatException` جديد وصل 🔔 (افتحه وشوف الـ stack trace — هاد اللي رح يقرأه الـ AI بعد شوي بدل عيونك).

### 2. وصّل عيون الـ AI — Sentry MCP

من التيرمينال (أي مكان):

```bash
claude mcp add --transport http sentry https://mcp.sentry.dev/mcp
```

بعدين افتح جلسة `claude` واكتب `/mcp` → اختار **sentry** → **Authenticate** → بيفتح متصفح، وافق بحسابك الجديد.

### 3. خلي الـ AI يقرأ الخطأ بنفسه

بنفس الجلسة اطلب:

> What are the latest unresolved issues in my Sentry? Show me the details of the most recent one and explain what happened in simple terms.

المفروض يجيب الـ `FormatException` تبعنا، يقرأ الـ stack trace، ويشرحلك: "الفيد بعت سعر بفواصل والكود بيتوقع رقم خام". **بدون ما تفتح Sentry بالمتصفح ولا مرة.**

### سؤال التثبيت

ليش استخدمنا MCP بدل ما ننسخ الـ stack trace يدوياً ونلصقه للـ AI؟ *(فكر بالدرس الجاي: التشخيص بده يصير أوتوماتيك — واللصق اليدوي معناه إنسان بالنص. الـ MCP بيشيل الإنسان من مرحلة "نقل المعلومة" ويخليه لمرحلة "القرار")*

## 🏢 كيف تنقلها لمشاريع الشركة

*(للمستقبل — بجلسة النقل المخصصة)*

نفس أمر `claude mcp add` بس المصادقة بحساب الشركة (بصلاحيات قراءة بس كبداية!) — وفجأة كل تاريخ أخطاء التطبيق قدام الـ AI: "شو أكثر 5 أخطاء تكراراً هالأسبوع؟"، "هاد الخطأ الجديد إله علاقة بريليز أمس؟". الدرس الجاي منبني عالهاد: من القراءة للتشخيص بالكود.
